# 프로토타입을 사용한 상속 구현

## 한 줄 정의

프로토타입 상속은 **부모의 공통 메서드를 자식이 사용할 수 있도록 프로토타입 체인을 연결하고,** 부모 생성자 호출을 통해 **부모가 초기화하는 인스턴스 프로퍼티도 자식 인스턴스에 생성하는 방식** 이다.

## 왜 사용하는가

부모와 자식이 공통된 값과 동작을 가질 때, 같은 코드를 자식마다 다시 작성하지 않고 재사용하기 위해 사용된다.

예를 들어 일반 사용자와 관리자가 있다고 하자.

- 일반 사용자와 관리자 모두 이름과 로그인 기록을 가진다.
- 일반 사용자와 관리자 모두 로그인과 로그아웃을 할 수 있다.
- 관리자만 사용자 삭제 기능을 가진다.

```
User
├─ name
├─ loginHistory
├─ login()
└─ logout()

Admin
├─ User의 기능 사용
├─ role
└─ deleteUser()
```

## 부모 생성자 함수

```js
function User(name) {
  this.name = name;
  this.loginHistory = [];
}
```

생성자 함수 내부에는 보통 **인스턴스마다 따로 가져야 하는 값** 을 작성한다.

- **name :** 사용자마다 값이 다름
- **loginHistory :** 사용자마다 별도의 배열이 필요함

```js
const user1 = new User("봄");
const user2 = new User("민수");
```

생성된 객체는 각자의 값을 가진다.

```
user1
├─ name: "봄"
└─ loginHistory: []

user2
├─ name: "민수"
└─ loginHistory: []
```

### 🤔 왜 값을 `prototype`에 넣지 않는가?

다음처럼 `name`과 `loginHistory`를 `User.prototype`에 넣을 수도 있다.

```js
function User() {}

User.prototype.name = "";
User.prototype.loginHistory = [];
```

그러면 모든 `User` 인스턴스가 해당 값을 프로토타입 체인을 통해 사용할 수 있다.

```js
const user1 = new User();
const user2 = new User();

console.log(user1.name); // ""
console.log(user2.name); // ""
```

하지만 문제가 있다.

#### 원시값은 겉보기에는 괜찮아 보인다.

```js
user1.name = "봄";

console.log(user1.name); // "봄"
console.log(user2.name); // ""
```

`user1.name = "봄"`을 실행하면 `User.prototype.name`을 수정하는 것이 아니라 `user1` 객체에 새로운 `name` 프로퍼티가 만들어진다.

```
user1
└─ name: "봄"

User.prototype
└─ name: ""
```

작동은 하지만 `name`은 처음부터 사용자마다 다른 값이 생기므로 생성자에서 직접 만드는 편이 자연스럽다.

#### 배열이나 객체는 모든 인스턴스가 공유하게 된다.

```js
function User() {}

User.prototype.loginHistory = [];

const user1 = new User();
const user2 = new User();

user1.loginHistory.push("로그인");

console.log(user1.loginHistory);
// ["로그인"]

console.log(user2.loginHistory);
// ["로그인"]
```

`user1` 과 `user2` 가 같은 배열을 사용하기 때문이다.

```
user1 ──┐
        ├─→ User.prototype.loginHistory
user2 ──┘              ↓
                    같은 배열
```

한 사용자의 로그인 기록을 추가했는데 다른 사용자의 기록에도 나타난다.
따라서 인스턴스마다 별도로 가져야 하는 배열이나 객체는 생성자 안에서 만든다.

## 공통 메서드는 `prototype` 에 저장

모든 사용자가 공통으로 사용하는 메서드는 `User.prototype` 에 작성한다.

```js
User.prototype.login = function () {
  this.loginHistory.push(new Date());
  console.log(`${this.name}님이 로그인했습니다.`);
};

User.prototype.logout = function () {
  console.log(`${this.name}님이 로그아웃했습니다.`);
};
```

`login()` 과 `logout()` 은 모든 사용자 객체가 같은 동작을 수행하므로 하나의 함수를 공유해도 된다.

```
user1 ──┐
        ├─ [[Prototype]] → User.prototype
user2 ──┘                    ├─ login()
                             └─ logout()
```

메서드는 하나만 존재하지만 호출한 객체에 따라 `this`가 달라진다.

```js
user1.login();
// this -> user1

user2.login();
// this -> user2
```

따라서 같은 메서드를 공유하면서도 각자의 `loginHistory`를 수정한다.

### 생성자와 `prototype`의 구분

1. **인스턴스마다 따로 가져야하는 상태**
   - 생성자 함수 내부의 this에 저장
2. **모든 인스턴스가 공유해도 되는 동작**
   - prototype에 저장

예를 들면 다음과 같다.

```js
function User(name) {
  this.name = name;
  this.loginHistory = [];
}

User.prototype.login = function () {};
User.prototype.logout = function () {};
```

## 자식 생성자 함수

관리자를 나타내는 `Admin` 생성자 함수를 만든다.

```js
function Admin(name) {
  User.apply(this, arguments);
  // call() 도 사용 가능
  this.role = "admin";
}
```

여기서 중요한 부분은 다음 코드다.

```js
User.apply(this, arguments);
```

`new Admin()`을 실행할 때 `this`는 현재 생성중인 `Admin` 인스턴스를 가리킨다.

`this -> 새로 생성되는 admin 객체`

`User.call(this, name)`은 `User` 생성자를 호출하면서 `User` 내부의 `this`도 현재 `admin` 객체를 가리키도록 한다.

```js
this.name = name;
this.loginHistory = [];
```

결과적으로 다음 값이 만들어진다.

```
admin
├─ name: "봄"          ← User 생성자가 생성
├─ loginHistory: []    ← User 생성자가 생성
└─ role: "admin"       ← Admin 생성자가 생성
```

## 부모 생성자를 호출하는 이유

프로토타입을 연결해도 부모 생성자 함수는 자동으로 실행되지 않는다.

```
new Admin()
→ Admin 생성자 실행
→ User 생성자는 자동 실행되지 않음
```

부모 생성자를 호출하지 않으면 다음 값이 생기지 않는다.

```js
function Admin() {
  this.role = "admin";
}

const admin = new Admin();

console.log(admin.name);
// undefined

console.log(admin.loginHistory);
// undefined
```

따라서 부모 생성자 내부에서 만드는 값이 자식에도 필요하다면 직접 호출해야한다.

```js
function Admin(name) {
  User.call(this, name);
  this.role = "admin";
}
```

부모 생성자 호출은 값을 복사하는 것이 아니다.

> 부모 생성자 함수를 현재 자식 인스턴스를 `this`로 지정하여 실행하는 것이다.

## 부모의 프로토타입 연결

부모 생성자를 호출했다고 해서 부모의 프로토타입 메서드까지 상속되는 것은 아니다.

```js
function Admin(name) {
  User.call(this, name);
}
```

이 상태에서는 `name`, `loginHistory` 는 존재하지만 `login()`은 사용할 수 없다.

```js
const admin = new Admin("봄");

console.log(admin.name);
// "봄"

admin.login();
// TypeError
```

`Admin.prototype` 과 `User.prototype`이 연결되어 있지 않기 때문이다.

따라서 프로토타입을 연결한다.

```js
Admin.prototype = Object.create(User.prototype);
```

`Object.create(User.prototype)`은 다음과 같은 새 객체를 만든다.

```
새로운 객체
└─ [[Prototype]] → User.prototype
```

이 객체를 `Admin.prototype`으로 설정한다.

```
Admin.prototype
└─ [[Prototype]] → User.prototype
```

이제 전체 프로토타입 체인은 다음과 같다.

```
admin
  ↓ [[Prototype]]

Admin.prototype
  ↓ [[Prototype]]

User.prototype
├─ login()
└─ logout()
```

따라서 `Admin` 인스턴스도 부모의 메서드를 사용할 수 있다.

```js
admin.login();
admin.logout();
```

## 메서드를 찾는 과정

```js
admin.login();
```

자바스크립트는 다음 순서로 `login`을 찾는다.

```
1. admin 객체에서 login 검색
   → 없음

2. Admin.prototype에서 login 검색
   → 없음

3. User.prototype에서 login 검색
   → 있음

4. User.prototype.login 실행
```

`login` 메서드가 `admin` 객체에 복사되는 것은 아니다.

프로토타입 체인을 따라 올라가서 찾아 사용하는 것이다.

## constructor 복구

다음 코드를 실행하면 기존 `Admin.prototype` 객체가 새 객체로 교체된다.

```js
Admin.prototype = Object.create(User.prototype);
```

원래 `Admin.prototype`에는 다음 프로퍼티가 자동으로 존재한다.

```
Admin.prototype.constructor -> Admin
```

하지만 프로토타입 객체를 교체하면서 이 연결이 사라진다.

따라서 다시 설정한다.

```js
Admin.prototype.constructor = Admin;
```

최종 구조

```
Admin.prototype
├─ constructor → Admin
└─ [[Prototype]] → User.prototype
```

## 자식만의 메서드 추가

관리자만 사용하는 기능은 `Admin.prototype`에 작성한다.

```js
Admin.prototype.deleteUser = function (user) {
  console.log(`${user.name} 사용자를 삭제했습니다.`);
};
```

## 전체 코드

```js
// 부모 생성자 함수
function User(name) {
  // 인스턴스마다 따로 가져야 하는 값
  this.name = name;
  this.loginHistory = [];
}

// 모든 User 인스턴스가 공유하는 메서드
User.prototype.login = function () {
  this.loginHistory.push(new Date());
  console.log(`${this.name}님이 로그인했습니다.`);
};

User.prototype.logout = function () {
  console.log(`${this.name}님이 로그아웃했습니다.`);
};

// 자식 생성자 함수
function Admin(name) {
  // 부모 생성자의 초기화 코드를
  // 현재 Admin 인스턴스에 실행
  User.call(this, name);

  // Admin 인스턴스만의 값
  this.role = "admin";
}

// Admin.prototype이 User.prototype을 상속하도록 연결
Admin.prototype = Object.create(User.prototype);

// constructor 복구
Admin.prototype.constructor = Admin;

// Admin 인스턴스가 공유하는 메서드
Admin.prototype.deleteUser = function (user) {
  console.log(`${user.name} 사용자를 삭제했습니다.`);
};
```

```
admin
├─ name: "봄"
├─ loginHistory: []
├─ role: "admin"
└─ [[Prototype]]
      ↓
Admin.prototype
├─ constructor: Admin
├─ deleteUser()
└─ [[Prototype]]
      ↓
User.prototype
├─ constructor: User
├─ login()
└─ logout()
```

## 책의 `inherit` 함수

책에서는 `Object.create()` 대신 빈 생성자 함수 `F`를 사용한다.

```js
function inherit(parent, child) {
  function F() {}

  F.prototype = parent.prototype;
  child.prototype = new F();
  child.prototype.constructor = child;
}
```

## 핵심 정리

```
부모 생성자 함수
→ 인스턴스마다 필요한 값 초기화

부모 prototype
→ 모든 인스턴스가 공유할 메서드 저장

부모 생성자 호출
→ 부모가 초기화하는 값을 자식 인스턴스에도 생성

프로토타입 연결
→ 부모의 공통 메서드를 자식이 사용할 수 있도록 연결

자식 prototype
→ 자식만의 공통 메서드 저장
```

## 값을 전부 `prototype`에 넣지 않는 이유

```
인스턴스마다 다른 값
→ 생성자 내부의 this에 저장

배열이나 객체 같은 개별 상태
→ 생성자 내부에서 새로 생성

모든 인스턴스가 공유해도 되는 메서드
→ prototype에 저장
```

최종적으로 다음 두 코드가 서로 다른 역할을 한다.

```
User.call(this,name);
```

> 부모가 인스턴스마다 만드는 값을 자식 인스턴스에도 생성한다.

```
Admin.prototype=Object.create(User.prototype);
```

> 부모의 공통 메서드를 자식 인스턴스가 찾아 사용할 수 있도록 프로토타입 체인을 연결한다.
