# 정적 메서드, 인스턴스 메서드와 속성 섀도잉

## 한 줄 정의

정적 메서드는 클래스 자체에서 호출하고, 인스턴스 메서드는 생성된 객체에서 호출한다.

객체의 프로퍼티가 프로토타입의 같은 이름 프로퍼티를 가리키는 현상을 속성 섀도잉이라고 한다.

## 1. 인스턴스 메서드

인스턴스 메서드는 **생성된 객체가 사용하는 메서드**이다.

```js
class User {
  constructor(name) {
    this.name = name;

    introduce() {
        console.log(`저는 ${this.name}입니다.`);

    }
  }

  const user = new User("봄");

  user.introduce();
}
```

클래스 내부에 일반적으로 선언한 메서드는 `User.prototype`에 저장된다.

```
user
  ↓ [[Prototype]]
User.prototype
  └─ introduce()
```

인스턴스 메서드의 `this` 는 메서드를 호출한 인스턴스를 가리킨다. (즉, 여기선 user을 가리킴)

## 2. 정적 메서드

정적 메서드는 인스턴스가 아니라, **클래스 자체에서 호출하는 메서드** 이다.

```js
class User {
  static isValidName(name) {
    return name.length >= 2;
  }
}

User.isValidName("김봄");
```

`static`으로 선언한 메서드는 `User.prototype`이 아니라, `User` 클래스 자체에 저장된다.

```js
User.isValidName;
User.prototype.isValidName; // undefined
```

주로 다음과 같은 기능에 사용한다.

- 값 검사
- 인스턴스 생성
- 데이터 변환
- 클래스와 관련된 공통 기능

## 3. 속성 섀도잉

속성 섀도잉은 객체 자신과 프로토타입에 같은 이름의 프로퍼티가 있을때, 객체 자신의 프로퍼티가 프로토타입의 프로퍼티를 가리는 현상이다.

```js
const parent = {
  name: "부모",
};

const child = Object.create(parent);

child.name = "자식";

console.log(child.name); // "자식"
console.log(parent.name); // "부모"
```

프로토타입의 값이 삭제된 것은 아니다. 프로퍼티 검색 과정에서 `child.name`이 먼저 발견되어 `parent.name`까지 올라가지 않은 것이다.

```
child
├─ name: "자식"   ← 먼저 발견
│
↓ [[Prototype]]
parent
└─ name: "부모"   ← 가려짐
```

## 4. 인스턴스 메서드에서 발생할 수 있는 섀도잉 문제

`hasOwnProperty()`는 `Object.prototype` 에 있는 인스턴스 메서드이다.

```js
const user = {
  name: "봄",
};

user.hasOwnProperty("name");
```

근데 객체가 같은 이름의 프로퍼티를 가지면 기존 메서드를 가릴 수 있다.

```js
const user = {
  name: "봄",
  hasOwnProperty: "일반 값",
};

user.hasOwnProperty("name");
// TypeError
```

검색 과정에서 객체 자신의 `hasOwnProperty` 가 먼저 발견되기 때문이다.

```
user
├─ hasOwnProperty: "일반 값"
│
↓ [[Prototype]]
Object.prototype
└─ hasOwnProperty()
```

## 5. `Object.hasOwn()` 사용 권장

속성 섀도잉 문제를 피하기 위해 정적 메서드인 `Object.hasOwn()`을 사용하는 것이 권장된다.

```js
const user = {
  name: "봄",
  hasOwnProperty: "일반 값",
};

Object.hasOwn(user, "name"); // true
```

`Object.hasOwn()` 은 검사 대상 객체에서 메서드를 찾지 않는다.

```
Object.hasOwn(검사할 객체, 프로퍼티 이름)
```

따라서 객체가 어떤 이름의 프로퍼티를 가지고 있어도 메서드가 가려지지 않는다.

또한 프로토타입이 없는 객체에서도 사용할 수 있다.

```js
const user = Object.create(null);

user.name = "봄";

Object.hasOwn(user, "name"); // true
```

## 정리

| 구분      | 인스턴스 메서드        | 정적 메서드                   |
| --------- | ---------------------- | ----------------------------- |
| 선언      | 일반 메서드            | `static` 사용                 |
| 호출      | `instance.method()`    | `Class.method()`              |
| 저장 위치 | `Class.prototype`      | 클래스 자체                   |
| 주요 용도 | 인스턴스의 상태와 행동 | 검사, 생성, 변환 등 공통 기능 |

```js
object.hasOwnProperty("name"); // 섀도잉 가능
Object.hasOwn(object, "name"); // 권장
```

> 객체에서 직접 메서드를 호출하면 같은 이름의 프로퍼티가 메서드를 가릴 수 있다.
> 따라서 객체를 인수로 받는 `Object.hasOwn()` 같은 정적 메서드를 사용하는 것이 더 안전하다.
