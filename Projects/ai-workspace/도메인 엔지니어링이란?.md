# 도메인 엔지니어링이란?

도메인 엔지니어링(DomainEngineering)은 소프트웨어 공학에서

> 특정 전문 분야(비즈니스 영역)에서 반복적으로 발생하는 문제들을 해결하기 위해, 공통된 뼈대와 규칙(인프라)를 설계하고 재사용 가능한 형태로 만드는 과정을 뜻한다.

쉽게 말해, 매번 새로운 프로그램을 바닥부터 새로 짜는 것이 아니라, 우리 비즈니스(도메인)만의 특수한 규칙과 작업 환경을 시스템레벨로 표준화하는 작업이다.

### 도메인(Domain)이란?

소프트웨어에서 도메인은 프로그램이 해결하고자 하는 **특정 업무 영역이나 지식의 범위**를 뜻한다.

- ex. 배달의민족의 도메인은 ‘주문/결제/라이더 배차’이다.
- 지금 프로젝트(`ai-workflow`)의 도메인은 ‘AI 에이전트가 코드를 고치거나 판단을 내릴 때, 사람이 안심하고 통제할 수 ㅇㅆ게 만드는 개발 거버넌스(Governance)이다.

### 일반 엔지니어링 vs. 도메인 엔지니어링

#### 일반 엔지니어링 (Application Engineering):

- “이번엔 쇼핑몰 AI 챗봇을 만들자” , “이번엔 코드 리뷰를 해 주는 AI 워커를 만들자”처럼 특정 하나의 앱을 구현하는 일이다.

#### 도메인 엔지니어링 (Domain Engineering):

- 어떤 에이전트 앱을 만들든 상관없이, 우리 도메인(거버넌스) 안에서 무조건 지켜져야 하는 “공통된 규칙과 불변의 법칙(Invariant)을 플랫폼으로 구축”하는 일이다.

### ai-workflow Project_v2 설계 = 도메인 엔지니어링의 정석

v2의 스팩은 도메인 엔지니어링의 핵심인 “비즈니스 규칙의 시스템화”를 보여주고 있다.

- 동일 조건 검증 법칙:
  - “판단을 비교하려면 무조건 같은 레포 스냅샷(`commitSha` )을 봐야한다”
    - 어떤 AI Specialist가 오든 이 규칙을 강제하는 틀을 만든다.
- 독립성 보장 법칙:
  - “specialist는 다른 specialist의 판단을 볼 수 없다”
    - 데이터 오염을 막기 위한 인프라적 제어
- 근거 중심의 데이터 구조화:
  - “근거가 없는 판단은 탈락시킨다(`EvidenceReference` 필수화”
    - LLM의 할루시네이션을 방어하는 고유의 규칙 설계

즉, “AI Agent를 데리고 코딩이나 리서치를 시킬 때, 우리 팀은 무조건 이 규칙과 단계를 거쳐서 일한다!”라는 공통 안전 기차 레일(하네스)을 설계하는 방식을 도메인 엔지니어링이라고 부른다.

개발 에이전트를 똑똑하게 만드는 것보다, 이 도메인 환경(레일)을 단단하게 만드는게 시니어 엔지니어링의 핵심 역량이다.
